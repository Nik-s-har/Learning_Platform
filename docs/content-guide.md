# Инструкция для редактора учебного контента

Привет! 👋 Эта инструкция поможет тебе безопасно менять содержание курсов
(тексты, видео, упражнения) через VS Code и GitHub. Программировать не нужно —
ты работаешь только с файлами контента. Главное — аккуратно соблюдать формат.

> ⚠️ Самое важное правило: **меняй только текст внутри кавычек**. Кавычки,
> запятые и скобки трогать нельзя — из-за одной лишней запятой проект перестаёт
> собираться. Если сомневаешься — лучше спроси, прежде чем сохранять.

---

## Что ты редактируешь

Файлы с контентом курсов лежат здесь:

```
src/courses/<название-курса>/data/<курс>Lessons.ts
```

Например, курс «Алфавит»:

```
src/courses/alphabet/data/alphabetLessons.ts
```

Это файл с расширением `.ts` — формально это код, но тебе нужна только часть
с данными уроков. Ниже подробно разберём её структуру.

---

## Часть 1. Разовая настройка (делается один раз)

1. Установи [GitHub Desktop](https://desktop.github.com/) **или** используй
   встроенный в VS Code «Source Control» (этого достаточно).
2. Авторизуйся в VS Code под своим GitHub-аккаунтом
   (значок аккаунта слева внизу → войти через GitHub).
3. Склонируй проект (если ещё не сделал(а) этого):
   - В VS Code: `Ctrl/Cmd + Shift + P` → набери **Git: Clone** →
     вставь ссылку на репозиторий → выбери папку на компьютере.
4. Открой папку проекта в VS Code.

> Запускать `npm install` и сам сайт тебе не обязательно — VS Code сам подсветит
> ошибки прямо в файле (см. раздел «Как проверить себя»). Но если хочешь видеть
> результат вживую, см. конец инструкции.

---

## Часть 2. Рабочий процесс — каждый раз, когда правишь контент

Делай по шагам, всегда одинаково:

### Шаг 1. Обнови проект до последней версии
Слева открой панель **Source Control** (иконка с веточками, `Ctrl/Cmd+Shift+G`).
Нажми «**…**» (три точки) → **Pull**. Это подтянет свежие изменения,
чтобы не было конфликтов.

### Шаг 2. Создай новую ветку под свою задачу
Внизу слева нажми на название текущей ветки (обычно `main`) →
**Create new branch** → дай понятное имя латиницей, например:
```
content/alphabet-lesson-2
```
Так твои правки не попадут сразу в основной проект, а пойдут на проверку.

### Шаг 3. Внеси изменения в файл контента
Открой нужный файл (например `alphabetLessons.ts`) и правь по правилам из
**Части 3**. Сохраняй файл `Ctrl/Cmd+S`.

### Шаг 4. Зафиксируй изменения (commit)
В панели **Source Control**:
1. В поле сверху напиши коротко, что сделал(а), например:
   `Урок 2: добавлены видео и 3 упражнения`.
2. Нажми галочку **Commit** (или кнопку «Commit»).

### Шаг 5. Отправь на GitHub (push)
Нажми **Sync Changes** (или «…» → **Push**). Твоя ветка появится на GitHub.

### Шаг 6. Создай Pull Request (запрос на проверку)
1. Зайди на github.com в репозиторий проекта — там появится жёлтая плашка
   «Compare & pull request» → нажми её.
2. Напиши, что изменила, и нажми **Create pull request**.
3. Сообщи разработчику, что PR готов к проверке.

После проверки твои правки добавят в проект (merge). Готово! 🎉

## Часть 3. Как устроен файл с уроками

Файл — это **список уроков**. Каждый урок выглядит так:

```ts
{
  id: 1,
  title: 'Урок 1',
  image: Tort,
  content: 'A, B, C, D',
  steps: [
    // шаги урока (видео и упражнения)
  ],
},
```

Разберём поля. **Менять можно текст внутри кавычек** `'...'`:

| Поле       | Что это                                              | Можно менять текст |
|------------|------------------------------------------------------|--------------------|
| `id`       | Номер урока. Должен быть **уникальным** (1, 2, 3 …)   | число, без кавычек |
| `title`    | Название урока, видно ученику                        | ✅ да              |
| `image`    | Картинка урока (см. ниже про картинки)                | особый случай     |
| `content`  | Короткое описание урока                              | ✅ да              |
| `steps`    | Список шагов урока (необязательное поле)              | см. ниже          |

### Шаги урока (`steps`)

Внутри `steps` идут шаги двух типов — **видео** и **упражнение**:

**Видео:**
```ts
{
  type: 'video',
  src: mediaUrl('courses/spotlite/alphabet/video/ABCD.mp4'),
  aboutLesson: 'Описание шага',
},
```
- `type: 'video'` — не меняем.
- `src: mediaUrl('...')` — внутри кавычек указываешь **путь к видеофайлу**.
  Сам файл видео должен быть заранее загружен в хранилище (об этом — разработчику).
  Здесь ты пишешь только путь, например `courses/spotlite/alphabet/video/ABCD.mp4`.
- `aboutLesson` — текст-описание, меняй свободно.

**Упражнение (Wordwall):**
```ts
{
  type: 'exercise',
  src: 'https://wordwall.net/embed/XXXXXXXX?themeId=1&templateId=3&fontStackId=0',
  aboutLesson: 'Описание шага',
},
```
- `type: 'exercise'` — не меняем.
- `src` — **полная ссылка на упражнение**. Как её взять: в Wordwall открой
  упражнение → **Share / Поделиться** → **Embed / Встроить** → скопируй адрес
  из `src="..."` внутри кода и вставь сюда между кавычками.
- `aboutLesson` — описание, меняй свободно.

## Часть 4. Типовые задачи

### ✏️ Изменить текст или ссылку
Найди нужное поле, меняй **только текст между кавычками**. Кавычки оставь.

```ts
content: 'Старый текст',   →   content: 'Новый текст',
```

### ➕ Добавить новый шаг в урок
Скопируй целиком существующий шаг (от `{` до `},` включая запятую в конце) и
вставь его рядом, затем поменяй содержимое. Пример — добавляем упражнение:

```ts
steps: [
  {
    type: 'video',
    src: mediaUrl('courses/spotlite/alphabet/video/ABCD.mp4'),
    aboutLesson: '...',
  },
  {
    type: 'exercise',
    src: 'https://wordwall.net/embed/НОВАЯ-ССЫЛКА',
    aboutLesson: '...',
  },   // ← не забудь запятую после блока, если за ним идут другие шаги
],
```
Правило: после каждого блока `{ ... }` в списке ставится запятая `,`.

### ➕ Добавить новый урок
Скопируй целиком блок одного урока (от `{` до `},`) и вставь его в конец списка,
**перед** закрывающей строкой `];`. Поменяй:
- `id` — следующий свободный номер (если последний был 7, поставь 8);
- `title`, `content` — свой текст;
- `steps` — свои шаги (или удали поле `steps`, если урок пока без шагов).

```ts
  {
    id: 8,
    title: 'Урок 8',
    image: Tort,
    content: 'Новый урок',
    steps: [
      // ...
    ],
  },
];   // ← эта строка всегда остаётся последней
```

### 🖼️ Про картинки уроков (`image`)
Сейчас все уроки используют одну картинку `Tort`. Для нового урока проще всего
**оставить `image: Tort`** — она уже подключена. Если нужна **новая** картинка,
это требует добавления строки-импорта в начале файла — лучше попроси
разработчика, либо договоритесь о готовом наборе картинок заранее.

## Часть 5. Как проверить себя перед отправкой

1. **Красные подчёркивания.** Если в файле есть красные волнистые линии или
   слева снизу горит красный кружок с числом ошибок — что-то сломано.
   Не отправляй такой файл, поищи где лишняя/недостающая кавычка или запятая.
2. **Подсветка скобок.** Поставь курсор рядом со скобкой — VS Code подсветит
   её пару. Так видно, что все `{ }` и `[ ]` закрыты.
3. **Сравни с соседним блоком.** Твой новый шаг/урок должен выглядеть один
   в один как соседний, отличаясь только текстом.

---

## Шпаргалка: что можно и что нельзя

✅ **Можно:**
- менять текст между кавычками (`title`, `content`, `aboutLesson`, ссылки);
- копировать целые блоки `{ ... }` и менять в них текст;
- менять номера `id` (только числа, уникальные).

🚫 **Нельзя:**
- удалять или менять кавычки `'`, запятые `,`, скобки `{ } [ ]`;
- менять слова-ярлыки слева от двоеточия (`type`, `src`, `title`, `content` …);
- менять значения `type: 'video'` и `type: 'exercise'`;
- удалять последнюю строку `];` в файле.

---

## Если что-то пошло не так

- **Случайно всё сломал(а)** — не паникуй и не отправляй. В панели Source Control
  можно нажать на файле «**Discard Changes**» (отменить изменения), он вернётся
  к исходному виду. Затем начни правку заново.
- **Не получается / непонятно** — напиши разработчику до того, как делать
  commit/push. Лучше спросить, чем сломать сборку.
